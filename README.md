#Front

I used Vue and Tailwind mainly to create the visual components. I have 3 pages instead of 2 which are main page sign in page and my account page. In my account apge user can change their passworrd and change the theme of the web application. Sign in page simply let users to sign in. I used firebase authentication as requested. I created a firebase project and incclude all the firebase secrets in .env file during development. After deployment I set them as environemnt variables. Most of the functionality is embedded in Home.vue file. In Home.vue file I Tailwind's prewritten classes to create rows for each parameters. I decided that it is a good idea to use modals when editing and deleting. Deleting simply prompts user that whether they are sure to delete the parameter. Edit is more comoplex. In edit modal, user can change value and description along with the country overrides. Country overrides is the bonus part of this case study. A user can add country and its specific value to the database. If there are lots of country overrides that is longer than the vertical viewport of the screen, then modal turns to be scrollable. All of the authentication is made using firestore as requested. When sending requests both firebase authentication token and custom API key created with "node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"" command are controlled. If one of them is missing or wrong, request will not be processed. I use firestore as database as requested. I used firestore's onSnapshot real time listener to update the view of each concurrent user at the same time. The details of the backend functions is explained in the backend repository.
